# experiments/ —— 文档级检索实验（BEIR 官方口径）

本目录实现《文档级检索实验方案.docx》的全部实验步骤，**全程不改动任何现有代码**
（rag_demo.py / indexes/dense.py / eval_retrieval.py 均未动），产物全部在本目录内。

## 背景：这一步要改变的本质

现有主程序是**块级检索**（17071 个块），与 BEIR 官方评测口径（**文档级**）不一致，
导致评测结果无法直接对照 BEIR 论文官方基线。本次实验把索引单位从块换成整篇文档，
用全量原始 qrels（12334 条，不截断）评测，数字可直接与官方基线对照。

| 维度 | 现在的块级口径 | 文档级口径（BEIR 官方） |
|---|---|---|
| 索引单位 | 17071 个块 | 3633 篇文档 |
| 检索返回 | Top-K 个块（约 10 篇文档） | Top-K 个文档 |
| 评测分母 | 相关块截断到 50 再映射 | 全量 12334 条原始 qrels |
| 可比对象 | 无（混合口径） | BEIR 官方基线，直接对照 |

## 目录结构

```

├── common.py                  公共模块：数据加载、向量化（断点续跑）、官方口径指标
├── doc_retrieval_full.py      第1步：方案A 整文档向量化
├── doc_retrieval_pool.py      第2步：方案B 块向量平均池化（含块级检索对照）

```

## 用法（在 experiments/ 目录下运行）

```bash
python doc_retrieval_full.py    # 方案A：3633 篇全文向量化（约3分钟，断点续跑）
python doc_retrieval_pool.py    # 方案B：复用块向量池化（约1分钟，零向量化成本）
python analyze.py               # A/B 对比 + 错误分析 + 实验总结（纯离线，秒级）
```

## 实验结果摘要（2026-09-01，nfcorpus，全量 qrels）

| 指标 | 方案A 全文向量化 | 方案B 块向量池化 | 块级对照(Top-50块) |
|---|---|---|---|
| NDCG@10 | **0.3867** | **0.3810** | 0.4352（口径混合，非官方） |
| Recall@10 | 0.1384 | 0.1398 | 0.1488 |
| Recall@50 | 0.2145 | 0.2132 | 0.2049 |
| Recall@100 | 0.2602 | 0.2676 | 0.2049 |
| 零召回题数 | 61/323 | 59/323 | 72/323 |

BEIR 官方 nfcorpus NDCG@10 基线：BGE-large-v1.5=0.380、SPLADE++=0.347、
BM25=0.325、TAS-B/GenQ=0.319、SBERT=0.272。

### 三个核心结论

1. **嵌入配置无损伤**：两方案 NDCG@10 均超过 BM25 基线（0.325），
   甚至略高于官方 BGE-large-v1.5（0.380）——裸模板（无指令前缀）不是大问题，
   实际表现超出实验方案预期的 0.27~0.33 区间。
2. **A≈B，池化可行**：差距仅 +0.0058（相对 +1.5%），逐题胜负 105:100 几乎五五开；
   按相关文档长度分桶后无一致趋势（相关系数 -0.119）。
   → **推荐方案 B（块向量平均池化）**：效果相当且零向量化成本，复用现有块向量即可。
3. **零召回 61 题多为数据集固有难题**：短查询词（如 "Alli"、"accidents"）与
   相关文档标题术语关联弱，属 nfcorpus 真实用户查询的固有难度，非本管线引入。
